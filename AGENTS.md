# Инструкции и регламент для AI-агентов (AGENTS.md)
# Проект: ONYX (SoundCloud Desktop Player)

Данный документ является главным регламентом и сводом правил для всех автономных AI-агентов, работающих с проектом **ONYX**.

---

## 1. Общие сведения и репозиторий

- **Название проекта**: ONYX (SoundCloud Desktop Player)
- **Репозиторий**: `qwezzxxx/soundcloud-desktop`
- **Рабочая папка проекта**: `F:\Soundcloud`
- **Локальный исполняемый файл**: `F:\Soundcloud\ONYX.exe`
- **Ветки разработки**:
  - `dev` — **активная ветка разработки**. Все доработки, исправления багов, изменения кода и предварительные сборки отправляются **исключительно сюда**.
  - `main` — **релизная ветка (продакшн)**. Обновляется и мержится строго после тестирования в `dev` и получения явного одобрения от пользователя. Прямые коммиты в `main` запрещены.

---

## 2. Ключи, токены и безопасность (Credentials)

В проекте пароли от аккаунтов не используются и нигде не сохраняются:

| Идентификатор / Токен | Назначение | Где хранится | Описание / Особенности |
|---|---|---|---|
| **GitHub PAT** | CI/CD, API GitHub | GitHub Secrets / Remote Origin | Настроен в remote origin и CI/CD Secrets.<br>Управление GitHub Actions, триггеры workflow, выгрузка собранных `.exe` |
| **SoundCloud OAuth Token** | Авторизация пользователя | Локально в `config.json` и `localStorage` (`oauth_token`) | Сессионный токен из куки `oauth_token`. Передаётся только напрямую в `api-v2.soundcloud.com`. Пароль от аккаунта не вводится |
| **SoundCloud Client ID** | Публичные запросы к API | Автоматически парсится Rust-бэкендом | Публичный ключ для метаданных треков, поиска и стримов без входа. Кэшируется и ротируется автоматически |

## 3. Архитектура и структура проекта

```
F:\Soundcloud\
├── ONYX.exe                       # Свежесобранный готовый бинарник под Windows
├── ui/                            # Интерфейс (Frontend)
│   ├── index.html                 # Основной интерфейс (TailwindCSS, Vanilla JS, SPA)

│   ├── tauri.conf.json            # Конфигурация окна, прав доступа и сборки
│   └── src/
│       ├── main.rs / lib.rs       # Инициализация Tauri, регистрация IPC-команд
│       ├── soundcloud.rs          # Модуль работы с API SoundCloud (поиск, треки, профили)

    ├── release.yml                # Сборка Windows EXE и создание релизов
    └── appimage.yml               # Сборка Linux AppImage
```

## 4. Реализованный функционал и архитектурные решения

### А. Аудиодвижок и потоки
- **Двухуровневый стриминг**:
  - *Первичный источник*: официальный SoundCloud API (HLS m3u8 / Progressive MP3).
  - *Фолбэк (`multi_providers`)*: если трек недоступен в регионе или заблокирован правообладателем, система автоматически находит оригинальное аудио на YouTube, фильтруя студийные версии и отдавая приоритет официальному каналу исполнителя (`Topic` / `Official Artist Channel`).
- **Управление воспроизведением**:
  - Плей, пауза, плавная перемотка, волновая шкала трека (`waveform progress`).
  - Очередь воспроизведения (`Queue Drawer`) с возможностью перемещения и очистки.
  - Умный Shuffle (перемешивание без повторений).
  - Repeat (зацикливание трека) с элегантной подсветкой кнопки плеера без лишних кружочков/бейджей.

### Б. Взаимодействие с профилем SoundCloud
- **Синхронизация медиатеки**: вход по OAuth токену, мгновенная синхронизация лайков (`Liked Tracks`) со статусом и количеством.
- **Моя Волна / Радио**: запуск радиопотока на основе любого трека (`seed track`) с непрерывной подгрузкой рекомендаций.

### В. Страница профиля исполнителя (Artist Profile)
- **Переход в профиль**: по клику на имя автора в нижнем плеере или через карточку исполнителя в поиске.
- **Компактная шапка**: оптимизирована под малые разрешения экрана (920×600, 1024×768), занимает минимум полезной высоты.
- **Аватар**: чистые скруглённые углы без лишних рамок, обводок и светящихся ореолов.
- **Статистика**: подписчики, количество треков, локация (город/страна), статус верификации.
- **Кнопки управления**:
  - «Слушать всё» — кнопка с контрастным чёрным текстом и иконкой на белом фоне (читается в любой теме).
  - «Перемешать» — случайный запуск дискографии.
- **Контент**:
  - Блок «Популярные треки» с номером, обложкой, длительностью, лайком и индикатором проигрывания.
  - Блок «Релизы и Альбомы».
  - Полноценный вертикальный скролл контейнера (контент не перекрывается нижним плеером).
  - Чистый дизайн без эмодзи (аккуратный текстовый бейдж `SC`).

### Г. Темы и кастомизация интерфейса
- **Наборы тем**: OLED Pure Black, Wine, Neon, Light, Flame, Amethyst и др.
- **Акцентный цвет**: настраиваемый цвет интерфейса.
- **Караоке и визуализация**: полноэкранный режим визуализации и синхронизированных текстов песен.

## 5. Регламент и рабочий процесс агента (Workflow Directives)

1. **Ветки и Git**:
   - Любые изменения кода производятся локально и пушатся **строго в ветку `dev`**.
   - **Запрещено** пушить напрямую в ветку `main`.
   - Слияние `dev` в `main` и выпуск публичного релиза производятся **исключительно после финального подтверждения пользователем**.
2. **Сборка и проверка**:
   - При пуше в `dev` запускается пайплайн сборки в GitHub Actions.
   - Свежий бинарник выгружается и тестируется по пути `F:\Soundcloud\ONYX.exe`.
3. **Безопасность файлов**:
   - Перед любым удалением или перемещением файлов верифицируйте точный путь.
   - Следуйте принципу **Read-Before-Write**: читайте файл перед модификацией, используйте точечное редактирование (`edit`) вместо слепой перезаписи.
   - Все текстовые файлы строго в кодировке `UTF-8` без BOM.
4. **Коммуникация**:
   - Чёткие, структурированные ответы на русском языке с ссылками на затронутые файлы.
